# pond-check · 鱼况体检

![Node >= 22](https://img.shields.io/badge/Node-%3E%3D%2022-339933?logo=node.js&logoColor=white)
![dependencies 0](https://img.shields.io/badge/dependencies-0-2ea44f)
![license MIT](https://img.shields.io/badge/license-MIT-blue)

**一句话**：pond-check 是一个**只读**的命令行体检工具——扫一遍你机器上所有在跑的 AI Agent（「鱼」），出一页体检报告：**谁活着 · 今天干了啥 · 哪儿坏了 · 怎么修**。

## 它不会做什么（先说边界，这是信任基础）

这比功能重要，所以放在最前面。五条承诺，逐条说具体：

1. **不联网（零网络请求）**——不上报、不统计、不遥测、不检查更新，一条网络请求都没有。生成的 HTML 报告也是**单文件零外链**（没有 script / link / img 引用），断网能打开，随便转发给别人也安全。
2. **不读凭证**——扫到凭证类文件（cookie、token、密钥、authorized_keys 这类）直接跳过：不打开、不读内容。文件名和路径**不会出现在任何输出里**，报告只写「已跳过 N 个凭证类文件」。唯一沾边的是「登录态新鲜度」检查：只看白名单里几个文件的**修改时间**，只输出「多少天没更新」，永不输出路径。
3. **不改任何东西**——不装插件、不改配置、不启停任何进程、**不写鱼目录里的任何文件**。唯一的写操作是**生成一份 HTML 体检报告**：默认写到当前目录，也可以用 `--out` 指定路径；除这份报告外，用户目录里的任何文件都不写。
4. **不做控制面**——不能重启她、不能改她的配置、不能替她登录。它是体检，不是手术：只诊断、只给「怎么修」的建议，动手的还是你。
5. **不做精确账单**——工作量只按判重表做**量级估算**（总条目、今天新增几条），报告里标注估算口径；不数 API 调用、不算钱。

## 它解决什么

养 AI 鱼最疼的不是「她不够可爱」，是这三件：

1. **「看起来在跑，其实什么都没发」** —— 静默失效，只能自己翻日志
2. **「不知道她今天到底干了啥」** —— 信息散在各处，日报只覆盖一小段
3. **「装完不跑，不知道为什么」** —— ffmpeg 没装？node 被顶替？登录过期？没人告诉你是哪个

pond-check 只做一件事：**把「看不见」变成「看得见」**。

## 它能诊断什么、不能诊断什么

写实，不吹：

**能诊断**：状态落在**本地文件系统**上的鱼——她有日志文件、有判重表（记录「干过哪些活」的那个文件）、有会话目录。典型如 AstrBot + NapCat 的 QQ 机器人、独立的挂机脚本、大多数常驻插件。工具顺着这些文件读出六格指标（见下文），每一格都给「所以呢，我现在该做什么」。

**不能诊断**（遇到这些，工具会**照实说判不出，绝不假装正常**）：

| 情况 | 工具会怎么说 | 下一步 |
|---|---|---|
| ① 状态存在数据库或远程服务里，本地没有日志/判重表 | 「无运行痕迹」「缺 日志」 | 用 `--root` 指定她的状态目录；她要是真不落本地文件，那这工具确实帮不上 |
| ② 只装了插件、从来没跑过（没有日志、没有判重表） | 「找到 N 个名字像鱼的插件，但没有任何运行痕迹……可能只是界面组件」 | 先确认这条鱼真的在跑（`ps aux` 里能看见她），再用 `--root` 指路 |
| ③ 名字里带 whale/fish、其实是界面组件的插件 | 同上，它会当「候选」列出来但不给假结论 | 不用管它；想只看真鱼，用 `--fish <名字>` 过滤 |

**通用下一步**就两句话：**用 `--root`（或 `--log` / `--dedupe`）把她的状态文件指给体检**；指完还读不到，就先确认这条鱼真的在跑、真的在写日志。

## 安装与用法

没有安装步骤——零依赖、零构建，克隆下来就能跑（Node >= 22）：

```bash
git clone https://github.com/LUgABeEEE/pond-check.git
cd pond-check
node src/cli.mjs --help      # 先看参数表、退出码与只读承诺
```

日常用法（每条都验证过，可直接粘贴）：

```bash
node src/cli.mjs             # 扫一遍，HTML 报告写到当前目录，stdout 打印文件路径
node src/cli.mjs --text      # 可贴群的纯文本摘要（stdout，人读）
node src/cli.mjs --json      # 完整 JSON（stdout，机器读）
node src/cli.mjs --out 报告.html   # 指定 HTML 报告的输出路径
```

> **报告会在当前目录累积**：默认模式每跑一遍就多一个 `pond-check-<YYYYMMDD-HHMMSS>.html`，跑得多了会堆起来。不用的随手清掉：`rm pond-check-*.html`（`.gitignore` 已忽略这个模式，不会误提交进仓库）；或者用 `--out 报告.html` 固定写到同一个位置——同名文件已存在会拒绝覆盖，确认要覆盖再加 `--force`。

自动扫没找全时的**逃生口**（指了就只体检这一条，不再重复扫）：

```bash
node src/cli.mjs --root <她的目录>       # 指窝：日志/配置/判重表都在这儿找
node src/cli.mjs --log <日志文件>        # 日志不在窝里、或名字不叫 *.log 时
node src/cli.mjs --dedupe <判重表文件>   # 判重表名字不符合惯例时
node src/cli.mjs --fish <名字>           # 只看名字里带这个词的鱼（按 id/窝路径/目录名匹配）
```

退出码：`0` 正常（扫到 0 条鱼也是 0）· `2` 参数用错 · `1` 真异常。

**想在任何目录直接敲 `pond-check`？** 在仓库目录里粘贴这段（把命令装到 `~/.local/bin`，不动系统目录）：

```bash
cat > ~/.local/bin/pond-check <<EOF
#!/bin/sh
exec node "$PWD/src/cli.mjs" "\$@"
EOF
chmod +x ~/.local/bin/pond-check
```


## 输出长什么样

**真实运行**（下面这段是真机原样复制的输出——这台机器上只有两个 DSH 插件、都从没跑过，所以工具诚实地说「无运行痕迹」，这正是它面对「不能诊断」时的样子）：

```text
🐟 pond-check · 2026-11-07 21:48 · linux/node 22.23.4
❓ widget（…105-1703）  判不出  缺 日志
❓ hale-widget（…web）  判不出  缺 日志
→ 最该做：dsh-whale-widget：用 --root 指明她的窝
    窝：~/.dsh/profiles/web-021-rollback-20261105-1703/node_modules/dsh-whale-widget
※ 找到 2 个名字像鱼的插件，但没有任何运行痕迹（无日志/无判重表/无会话），可能只是界面组件。
※ 12 项数据读不到（存活、节律、工作量、健康、漂移、依赖），不能当正常。
※ 认不出 = 存活与工作量两格都判不出（不是没这条鱼）。
共 2 条，活跃 0 / 疲软 0 / 坏了 0 / 认不出 2。
```

**⚠️ 下面这段是造的数据**（合成 4 条鱼跑出来的示例，**不是真机结果**），用来展示四种状态同时出现时长什么样：

```text
🐟 pond-check · 2026-11-07 20:00 · linux/node 22.23.4
🔴 qq-fish-01（web）     坏了           9 天未干活  日志 风控拦截 ×3
⚠️ bili-whale-02（web）  疲软 3 小时前  今天 0 条   今天没干活
❓ desktop-pet           判不出                     缺 日志
✅ bili-whale-01（web）  活跃 1 分钟前  今天 3 条   依赖 齐了
→ 最该做：qq-fish-01（web）：进程不在就按启动命令拉起
※ 找到 1 条名字像鱼的候选，但没有任何运行痕迹（无日志/无判重表/无会话），可能只是目录占位。
※ 7 项数据读不到（节律、存活、工作量、健康、漂移、依赖），不能当正常。
※ 认不出 = 存活与工作量两格都判不出（不是没这条鱼）。
共 4 条，活跃 1 / 疲软 1 / 坏了 1 / 认不出 1。
```

怎么读：行首图标是这条鱼的**总体结论**（✅ 活跃 / ⚠️ 疲软 / 🔴 坏了 / ❓ 认不出），后面三列分别是「存活」「工作量」和一句「出了什么事」。`→ 最该做` 只给一条最优先的行动；`※` 行是数据口径说明——「判不出」永远不当「正常」。`--json` 里有全部细节（含每格的证据），HTML 报告（默认输出）是一页深色图，适合直接发群里。

## 六指标

每条鱼体检这六格，每格给「档位 + 现象 + 下一步」：

| 指标 | 看什么 | 可能的结论 |
|---|---|---|
| **存活** | 她最后一次活动是什么时候（日志/判重表/会话文件的时间戳，取最新） | 活跃 · 疲软 · 疑似休眠 · 死了 · 判不出 |
| **节律** | 近 7 天按天统计的活动分布，作息稳不稳 | 规律 · 散架 · 偶尔回魂 · 全停 · 判不出 |
| **工作量** | 判重表条目数与今天新增（量级估算） | 在干活 · 今天歇着 · 停摆 · 空账本 · 判不出 |
| **健康** | 最近 24 小时日志里的报错按类计数（登录失效/风控拦截/被限流/验证码/熔断/运行报错/系统报错） | 干净 · 有点吵 · 有病 · 已经挂了 · 判不出 |
| **依赖** | 六项体检：ffmpeg、Node 版本、登录态新鲜度、窝可写、模型线路、磁盘余量 | 齐了 · 有隐患 · 坏了 · 判不出 |
| **漂移** | 配置版本与程序版本对不对得上、有没有旧字段残留 | 对齐 · 落后 · 对不上 · 判不出 |

判不出的格会写明**缺什么数据**（比如「缺 日志」），并进脚注统计——判不出不是正常。

## 常见症状怎么读

| 症状 | 看哪个指标 | 怎么办 |
|---|---|---|
| 群里没动静，但她看着在跑 | 存活 + 工作量 | 「活着但今天 0 条」→ 翻日志最后 20 行看有没有报错；「坏了」→ 进程不在就按启动命令拉起，进程还在就翻日志最后的报错（多半是登录过期或依赖缺失） |
| 日志一直刷 412 / 验证码 | 健康 | 按类别修：换新 cookie、把请求间隔调大到 5 秒以上；验证码得人工过一次、存好新登录态 |
| 装完就不跑 | 依赖 | 看六项哪条红了：ffmpeg 没装 → `apt install ffmpeg`（Debian/Ubuntu）或 `brew install ffmpeg`（macOS）；Node 版本低 → `nvm install 22 && nvm use 22`，然后重启她 |
| 升级后行为怪、配置报错 | 漂移 | 先备份配置，再跑一次她的迁移命令；没有迁移命令就按报告里的改名表手动改字段名 |
| 报告全是「判不出」 | （缺数据） | 用 `--root <她的目录>` 指定她的窝，或 `--log` / `--dedupe` 单独指文件；指完还读不到 → 检查路径对不对、权限够不够、她是不是真的在写日志 |
| 判重表是空的 | 工作量 + 依赖 | 先补依赖（ffmpeg、登录态、模型线路），再手动触发一次，看第一条能不能写进去 |
| 同一条鱼出了两张卡 | —— | 用 `--fish <名字>` 只看一条；同一个窝里跑多个实例是正常的 |

## 开发

- **Node >= 22**（package.json 的 engines 已声明），**零运行时依赖、零构建步骤**——改完直接跑。
- 测试：`npm test`（内部就是 `node --test`，零依赖，不联网）。
- 代码走向：`src/discover`（发现鱼）→ `src/read`（读窝里的日志/配置/判重表）→ `src/evaluate`（六指标判定，阈值全部在 `src/rules.json`）→ `src/render`（HTML / 文本 / JSON 三种输出）→ `src/cli.mjs`（入口）。
- 规格与设计在 `docs/SPEC.md`；首次使用走查记录在 `docs/FIELD-NOTES.md`。
- 能力层（记忆 / 唤醒 / 语音 / 出图）的设计稿在 `docs/CAPABILITIES-SPEC.md` —— **未实现的设计稿，v0.1 不含这些能力**：那是第二期的设计基线，不是功能清单，别照着它敲命令。
